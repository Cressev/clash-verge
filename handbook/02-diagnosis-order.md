# 02. Diagnosis Order

最省时间的排查顺序是：

1. 先看 DNS。
2. 再看规则。
3. 再看 TUN 路由。
4. 最后才看具体应用的代理环境。

## 为什么这样排

- DNS 错了，后面基本都在白忙。
- 规则写了 `DIRECT`，不代表流量真的没被 TUN 拦走。
- 终端里看起来能访问，不代表应用继承了同一套代理变量。

## 快速分类

- `nslookup` 返回 fake-ip: 优先修 DNS。
- 域名和进程都写了 `DIRECT` 但还是不通: 优先查 TUN / route-exclude。
- 只有某个工具不通: 查 wrapper、环境变量和实际运行路径。
